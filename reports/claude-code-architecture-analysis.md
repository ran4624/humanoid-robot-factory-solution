## 一、产品概述

### 1.1 什么是 Claude Code

Claude Code 是 Anthropic 推出的**代理式编程工具(Agentic Coding Tool)**，可以直接读取代码库、编辑文件、运行命令并与开发工具集成。它代表了 AI 辅助编程从"工具"向"智能体"的范式转变。

### 1.2 核心定位

- **产品形态**: 终端 CLI、VS Code 插件、桌面应用、Web 应用、JetBrains 插件
- **目标用户**: 软件工程师、开发团队
- **商业模式**: 订阅制，年收入运行率超过 5 亿美元
- **使用规模**: Anthropic 内部 90% 的代码由 Claude Code 编写

### 2.3 技术选型分析

**为什么选择 React + Ink？**
- 将 Web 前端开发经验迁移到终端 UI
- 组件化思想提高代码复用性
- 140+ 个 UI 组件，规模相当于中型 Web 应用

**为什么选择 Bun？**
- 高性能 JavaScript 运行时
- 内置打包和 TypeScript 支持
- 更快的启动速度和执行效率

## 三、核心架构设计

### 3.1 架构哲学

Claude Code 的核心设计理念可以概括为：

> **"一个简单、单线程的主循环，配合规范的工具和规划，实现可控的自主性"**

这与当前流行的复杂多智能体(Multi-Agent)系统形成鲜明对比，Claude Code 选择了一条**简洁优先**的路径。

### 3.2 六层架构体系

```
┌─────────────────────────────────────────────────────────────┐
│  1. 交互层 (Interaction Layer)                               │
│     - CLI、VS Code 插件、Web UI、桌面应用、JetBrains 插件      │
├─────────────────────────────────────────────────────────────┤
│  2. 核心引擎层 (Core Engine)                                 │
│     - nO: 主循环 (Master Loop)                              │
│     - h2A: 实时转向系统 (异步双缓冲队列)                       │
│     - wU2: 上下文压缩器 (Compressor)                         │
│     - StreamGen: 流式输出生成                                │
├─────────────────────────────────────────────────────────────┤
│  3. 工具系统层 (Tool System)                                 │
│     - 40+ 工具: Bash、文件读写、Grep、Glob、Web 搜索等         │
│     - 声明式工具定义 (Schema + 权限模型)                      │
├─────────────────────────────────────────────────────────────┤
│  4. 上下文管理层 (Context Management)                        │
│     - 三层存储: 短期记忆 + 中期记忆 + 长期记忆                  │
│     - 8段式压缩总结，压缩比 20%                               │
├─────────────────────────────────────────────────────────────┤
│  5. 规划与执行层 (Planning & Execution)                      │
│     - TodoWrite: 结构化任务列表                               │
│     - I2A: 子代理调度 (Task Agent)                           │
├─────────────────────────────────────────────────────────────┤
│  6. 安全与权限层 (Safety & Permissions)                      │
│     - 风险分级 + 确认提示                                     │
│     - 命令注入防护                                            │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 核心组件详解

#### 3.3.1 主循环 (nO - Master Loop)

```typescript
// 核心逻辑伪代码
while (true) {
  const response = await claudeAPI.send(messages);
  
  if (response.hasToolCalls()) {
    // 执行工具调用
    const results = await executeTools(response.toolCalls);
    messages.push({ role: 'assistant', content: response });
    messages.push({ role: 'user', content: results });
  } else {
    // 纯文本响应，任务完成
    return response.text;
  }
}
```

**设计要点**:
- 单线程执行，避免并发复杂性
- 扁平消息历史，无线程对话
- 工具调用即循环，文本响应即终止

#### 3.3.2 实时转向系统 (h2A)

**h2A** 是异步双缓冲队列系统，允许用户在 Agent 执行任务时进行干预：

- **功能**: 中途注入新指令、约束或方向调整
- **实现**: 异步队列 + 主循环协作
- **价值**: 解决生产环境中自主系统的可控性问题

#### 3.3.3 上下文压缩器 (wU2)

当上下文窗口使用率达到 **92%** 时自动触发：

1. **压缩策略**: 对话总结 + 重要信息提取
2. **长期存储**: Markdown 文档作为项目记忆
3. **避免方案**: 不使用向量数据库或嵌入检索，保持简单

## 四、工具系统设计

### 4.1 工具分类

Claude Code 包含 **40+ 个工具**，分为以下几类：

#### 4.1.1 读取与发现工具

| 工具 | 功能 | 说明 |
|-----|------|------|
| **View** | 文件读取 | 默认约 2000 行 |
| **LS** | 目录列表 | 文件系统浏览 |
| **Glob** | 通配符搜索 | 大规模仓库搜索 |
| **GrepTool** | 正则搜索 | 类 ripgrep 能力，非向量搜索 |

**设计洞察**: 不使用向量数据库，依赖 Claude 的代码理解能力生成复杂正则模式。

#### 4.1.2 代码编辑工具

| 工具 | 功能 |
|-----|------|
| **Edit** | 精确补丁/差异编辑 |
| **Write/Replace** | 整文件操作 |
| **New File** | 创建新文件 |

**特点**: 显示最小差异，支持回滚，保持输出可读性。

#### 4.1.3 执行工具

| 工具 | 功能 | 安全机制 |
|-----|------|---------|
| **Bash** | Shell 命令执行 | 风险分级 + 确认提示 |
| **Task** | 子代理调度 | 深度限制防止递归爆炸 |

**安全防护**: 过滤注入攻击，阻止反引号和 shell 扩展构造。

### 4.2 工具调用流程

```
用户请求
    ↓
Claude 生成工具调用 (JSON)
    ↓
ToolEngine 调度执行
    ↓
沙箱环境执行
    ↓
返回纯文本结果
    ↓
追加到消息历史
    ↓
循环继续
```

## 五、上下文与记忆系统

### 5.1 三层记忆架构

| 层级 | 存储方式 | 用途 | 容量 |
|-----|---------|------|------|
| **短期记忆** | 当前对话上下文 | 当前会话的完整历史 | 上下文窗口 |
| **中期记忆** | 8段式压缩总结 | 跨会话项目知识 | 压缩比 20% |
| **长期记忆** | Markdown 文档 | 持久化项目记忆 | 无限制 |

### 5.2 自动内存 (Auto Memory)

Claude Code 会自动构建跨会话记忆：

- **构建命令**: 记录项目构建方式
- **调试见解**: 保存调试经验
- **代码模式**: 识别项目特定模式
- **重复问题**: 记录常见错误和解决方案

### 5.3 CLAUDE.md

项目根目录的 `CLAUDE.md` 文件：
- 编码标准
- 架构决策
- 首选库
- 审查清单
- 每个会话自动读取

## 六、子代理 (Subagent) 系统

### 6.1 架构设计

Claude Code 采用**分层多 Agent 架构**：

```
用户请求
    ↓
主 Agent (nO 循环)
    ↓
    ├─→ 直接处理 (简单任务)
    │
    └─→ Task 工具 → 创建 SubAgent (I2A)
                         ↓
                    独立上下文窗口
                         ↓
                    返回结果
```

### 6.2 内置 Subagents

| Subagent | 模型 | 工具权限 | 用途 |
|---------|------|---------|------|
| **Explore** | Haiku | 只读 | 快速代码库探索 |
| **Plan** | 继承主对话 | 只读 | Plan Mode 研究 |
| **General-purpose** | 继承 | 全部 | 复杂多步骤任务 |
| **Bash** | 继承 | Bash 专用 | 隔离执行命令 |

### 6.3 Subagent 配置

```yaml
---
name: code-reviewer
description: 代码审查专家，主动在代码变更后使用
memory: user
tools: [Read, Grep, Glob, Bash]
model: sonnet
---

你是一名资深代码审查员，专注于代码质量、安全性和最佳实践...
```

### 6.4 设计原则

- **独立上下文**: 每个 Subagent 在自己的上下文窗口运行
- **工具限制**: 可限制 Subagent 可访问的工具
- **权限隔离**: 独立的权限模式
- **深度限制**: 防止递归生成 Subagent

## 八、安全与权限系统

### 8.1 六层防护体系

1. **命令注入防护**: 过滤危险字符和构造
2. **风险分级**: Bash 命令分类为安全/警告/危险
3. **确认提示**: 危险操作需用户确认
4. **沙箱执行**: 工具在隔离环境运行
5. **权限模式**: 只读/建议/自动执行
6. **审计日志**: 完整操作记录

### 8.2 权限模式

| 模式 | 说明 |
|-----|------|
| **Read-only** | 仅读取，无修改 |
| **Suggest** | 建议修改，用户确认后执行 |
| **Auto-edit** | 自动执行文件编辑 |
| **Auto-execute** | 自动执行所有操作 |

## 十、架构对比与启示

### 10.1 与 Multi-Agent 系统的对比

| 维度 | Claude Code | 典型 Multi-Agent |
|-----|-------------|-----------------|
| **架构** | 单线程主循环 | 多 Agent 并行 |
| **复杂度** | 低 | 高 |
| **可控性** | 高 | 中 |
| **调试性** | 易 | 难 |
| **透明度** | 高 | 中 |
| **扩展性** | 受控并行 | 自由扩展 |

### 10.2 核心启示

1. **简洁优先**: 简单的架构更容易调试和维护
2. **模型为核心**: Agent 是模型，不是框架或提示链
3. **可控自治**: 通过工具、规划和权限实现可控的自主性
4. **Harness 设计**: 工程师的工作是构建"线束"(Harness)，让模型发挥作用

### 10.3 设计原则总结

```
Agent = Model (神经网络，通过训练学习行动)
Harness = Tools + Knowledge + Observation + Action + Permissions

模型决定，线束执行
模型推理，线束提供上下文
模型是司机，线束是车辆
```
